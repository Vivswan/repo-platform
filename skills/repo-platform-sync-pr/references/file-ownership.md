# File classes and the decision rule per class

<!-- The Class and Files columns are one roster with skills/repo-platform-new-project/references/file-ownership.md (skills install standalone, so each ships its own table); the platform's check_ssot skill-ownership-tables rule fails on any difference between the two. The third column is this skill's own. -->

Classify every file a sync PR touches before deciding what to do with a surprising row. The Written section names each path's class; this table says what the class means for the decision.

| Class | Files | Decision rule in a sync PR |
|---|---|---|
| Managed (rewritten whole every sync) | `.github/workflows/ci.yml`, `.github/dependabot.yml`, `.github/instructions/review.instructions.md`, `.yamllint`, `.typography-allow`, `.github/workflows/auto-assign.yml`, `.github/settings.yml` (rendered from the fleet settings layers and `.github/settings.local.yml`), the module workflows (`deno-audit.yml`, `pr-title.yml`), the toolchain pin dotfiles (`.bun-version`, `.dvmrc`), `.github/repo-platform-manifest.json` (the record of what the platform wrote) | Accept the platform version. `created`, `updated`, and `unchanged` need no look; `replaced local edits` shows the diff of what someone wrote there, and that content moves into a repo-owned hook, into `.github/settings.local.yml` for a setting, or into the platform's `files/` |
| Split (managed region, repo-owned tail) | `.editorconfig`, `.gitattributes`, `.gitignore`, `.github/CODEOWNERS`, `AGENTS.md`, `LICENSE.md` (not with `custom-license`) | Only the region between `BEGIN REPO-PLATFORM MANAGED` and `END REPO-PLATFORM MANAGED` changes; the diff must stay inside the markers. Content above BEGIN and below END rides through byte-for-byte. An edit inside the region reads `replaced local edits` with its diff, like a managed file |
| Starter (written once, then repo-owned) | `.github/workflows/checks.yml`, `post-green.yml`, `update-release.yml`, `update-release-pr.yml`, `.github/actions/site-build/action.yml` (the site-build hook), `copilot-setup-steps.yml`, `auto-format.yml` (formatter toolchains), `.gitleaks.toml`, `.github/actionlint.yaml`, `.github/settings.local.yml`, `release-please-config.json`, `.release-please-manifest.json`, `nightly-fuzz.yml`, `nightly.yml` | `created` when the path was absent (a new module or a first sync explains it), `unchanged` when it exists; never `updated` or `replaced local edits`. A starter row that modifies or deletes an existing file is a sync bug; stop and report |
| Repo-owned, read by the platform | `.repo-platform.yml` | Never in the diff: the sync reads it and rewrites nothing |
| Mirror | the targets declared under `mirrors` in `.repo-platform.yml` | `written` and `current` are routine; `replaced local edits` shows the replaced content's diff and `replaced` names the directory or blocking file removed, both holding the PR. A declaration the writer cannot honour fails the sync instead of appearing here |

Retired rows (the Retired section) follow the same ownership: a `deleted` row removed the platform's own content, a `region removed` row took the managed region out of a split file and left your content as a plain file, a `held` row found content the platform did not write and left the file for you, a `kept` row is a starter (yours), a `moved` row renamed the file with git.
